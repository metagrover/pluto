# PR #676: useful local notes baseline

## Delivery decision

The user approved a practical first improvement, not another model-comparison round. Promote Gemma 4 12B for meeting notes and make ordinary content-quality disagreements recoverable after the existing correction attempt. Keep questionable commitments out of confirmed task/decision lists, preserve useful reviewed notes, and retain hard failures for broken contracts and source references.

This supersedes the draft-only promotion decision in the earlier relative-results report. Those historical measurements remain unchanged.

## Scope

- Production local writer/audit path only; one existing repair attempt per stage.
- Gemma is pinned for note requests and run identity. Generic model settings, non-note tasks, hosted providers and the opt-in editor are unchanged.
- Recognized semantic warnings survive every hierarchy node and final publication through quality issues and `complete_with_warnings`.
- No unchecked writer fallback, partial-meeting success, fabricated replacement tasks or new UI notice.
- No new inference, model download, production regeneration, settings change or database rewrite in this revision.

## Saved-response evidence

The new public regression replays all four immutable Gemma response sequences from `meetingNotesRelativeCandidateSeed41.json` through the actual pipeline, decoding their original source labels.

Before implementation: three passed; qualified publication failed with `notes_audit_invalid`. After implementation: all four complete. Qualified publication uses the original three responses, retains reviewed prose, excludes the task missing its prerequisite, records warnings, and does not claim that task was repaired.

The three earlier private meeting runs stopped after 3, 5 and 3 responses. An offline harness verifies each captured stream reconstructs the exact saved response, replays those responses without modification, and checks that processing advances to a new writer/merge stage after the former rejection. All three pass this continuation check. The harness deliberately stops when saved responses run out.

**These are not three complete new meeting outputs.** Saved-response recovery does not establish end-to-end real-meeting fidelity, fresh model quality, or new inference latency. Private sources and reports remain outside the repository.

A read-only comparison against the original snapshot confirms all three meetings' selected source, saved notes, edits and model/version fields remain unchanged.

## Accepted limitations

Local notes can omit useful context or make mistakes. Source references establish traceability, not proof that every paraphrase is correct. Recoverable warnings may mean an otherwise useful document has fewer confirmed tasks. Future prompt improvements can address these gaps without blocking this baseline.

The original four-case whole-system comparison favored the candidate in three examples; it did not isolate model-only effects or demonstrate universal reliability. No historical evaluation score is changed by these replays.

No fresh rendered-app or complete private-recording generation pass is claimed for this revision. Earlier disposable-profile UI/history checks are historical evidence only.
