## Affected surfaces

- Recording workspace: live history, draft text, Return to live, and navigation during recording.
- Stop/finalization and reopened meeting: final transcript, speaker review and generated notes.
- Live suggested labels: only after the separate #770 feasibility gate passes.

## Critical #670 journeys

1. Record a consented loudspeaker call with alternating local replies and remote speech. Every local contribution remains readable, and independently supported remote echo spans appear once after reconciliation.
2. Commit mic speech before the other channel/evidence arrives. Later correction updates the existing row in place. Withdrawal of support restores the original words once. Existing rows do not reorder.
3. Scroll back while recording. Trigger a correction above the viewport. Keep the visible reading anchor and keyboard focus. Return to live resumes following only when requested.
4. Speak a long unfinished sentence. The collapsed draft remains compact; expansion exposes the full current draft. Committing it preserves all words.
5. Navigate away and back without stopping. Preserve session history and prevent replay duplicates. Start a new recording after stop and verify no old draft, label or callback leaks into it.
6. Trigger a live presentation failure or a failed source. Recording remains sealable; the visible state accurately reports unavailable/degraded live output. Stop, wait for finalization, reopen, and verify the final transcript and notes use trusted canonical evidence.

## Negative and boundary cases

- Headphones; remote-only loudspeaker; overlap; sustained remote monologue with brief local interruptions; long-session load.
- Genuine repeated phrases, negations, signed/numeric/currency wording and missing word timing. Uncertain speech must be retained rather than hidden to improve a duplicate metric.
- Tentative counterpart disappears; entire displayed row retracts and then restores; an initially hidden row becomes late visible speech.
- Setting off or unavailable at start; no mid-meeting rendering mode switch.
- Narrow window, reduced motion, keyboard draft expansion and Return to live. Status announcements must not repeatedly read the transcript body.

## #770 feasibility and conditional journeys

Before any production names: run consented held-out known, unseen and similar-voice cases with concurrent real EOU; compare latency, queues, memory, model preparation and stop behavior against the same baseline. Count distinct clean evidence rather than repeated overlapping snapshots. Missing private data is NOT RUN; no suggestions is not a useful accuracy pass.

After feasibility: test a remote speaker handoff within one text row, overlap, rolling cluster split/merge, delayed/expired hints, same audio repeated in new windows, and rejection followed by a changed digest. Never apply a whole-row name from partial interval overlap. Disable/delete/merge/restore a profile while analysis is in flight and while silent; affected names must be revoked. Stop/reset/owner loss must discard late hints and leave final Speaker Review as the only confirmation/enrollment path.

## Evidence rules

Use synthetic words/vectors in committed tests. Private audio and identities remain local and consented. Store only aggregate counts/durations, pass/fail and failure categories in shareable reports; no text, names, meeting IDs, paths, embeddings, raw scores or candidate digests.

Do not label skipped tests or absent corpus runs PASS. Synthetic scheduling and DOM tests do not substitute for real FluidAudio resource measurements or Electron scroll/finalization evidence.
