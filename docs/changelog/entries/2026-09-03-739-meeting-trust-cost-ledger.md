### Expose duplicate model work in trusted meeting notes

- **Issue:** [#739](https://github.com/metagrover/pluto/issues/739)
- **PR:** [#740](https://github.com/metagrover/pluto/pull/740)
- **Changed:** A deterministic repository report now separates capture sealing, canonical transcript finalization, trusted-note generation, and post-publication enrichment while accounting for note-stage model calls, tokens, repeated source consumption, repairs, identical recovery outputs, and a benchmark-only deterministic recovery replay. The private latency runner can explicitly opt into that recovery hook and reports successful recoveries separately from model repairs.
- **Why:** A single stop-to-notes total can misattribute capture or transcription delay to notes generation, while aggregate retry counts hide expensive repairs that reproduce the rejected response unchanged.
- **Replaced:** Ad hoc inspection of captured note attempts without an explicit privacy-safe timing and recovery ledger.
- **Notes:** The initial committed synthetic editor captures measure only canonical-to-trusted-notes work. Other boundaries remain explicitly unavailable. The replay mechanically recovered all four duplicate writer-repair candidates through the existing strict parser and source guardrails, representing 177,875 ms of captured repair-model time; it correctly refused the one duplicate audit repair, representing 31,747 ms. A completed read-only 33-minute recent-meeting run used eight model calls over 664,654 ms, recorded no repairs, and failed at merge commitment preservation. A second historically repair-prone recent-meeting probe was stopped after more than 30 merge calls; it did not establish a real-meeting recovery gain. Structural recovery and guardrail passage do not establish semantic correctness or authorize production parser changes.
- **Safety:** The deterministic report makes no model or database calls. The private latency runner opens the production database read-only, writes only an owner-readable content-free report outside the repository, and requires an explicit recovery flag. Product behavior is unchanged, and reports reject transcript, prompt, response, evidence, participant, private-path, or sentinel content.
