### Bound and expose model work in trusted meeting notes

- **Issue:** [#739](https://github.com/metagrover/pluto/issues/739)
- **PR:** [#740](https://github.com/metagrover/pluto/pull/740)
- **Changed:** A deterministic repository report separates capture sealing, canonical transcript finalization, trusted-note generation, and post-publication enrichment while accounting for note-stage model calls, tokens, repeated source consumption, repairs, and identical recovery outputs. Direct meetings now use one compact source-backed writer and one complete-document editor on the same configured model.
- **Why:** The ledger showed that repairs and merge cascades consumed substantial time, while the compact-writer benchmark showed a large warm speed and output-token improvement but unsafe semantic variation when used alone. One complete-document editor retains a semantic correction pass without a patch ledger or direct-path repair, merge, and repartition calls.
- **Replaced:** Ad hoc performance inspection and the unbounded direct writer/audit/repair route are replaced by a privacy-safe ledger and a two-call direct pipeline.
- **Notes:** The initial synthetic captures measured only canonical-to-trusted-notes work. A read-only 33-minute run used eight model calls over 664,654 ms and failed at merge commitment preservation; a repair-prone meeting exceeded 30 merge calls. The compact writer then completed a read-only 14-minute meeting in 55,556 ms warm but exposed omissions and false commitment promotion, which is why the editor remains required. Oversized inputs retain the existing hierarchy during this iteration.
- **Safety:** Direct writer and editor failures preserve existing notes without a model repair call. Exact source decoding, schema checks, narrow commitment guardrails, stale-source protection, and transactional publication remain required. The report makes no model or database calls, private benchmarks keep the production database read-only, and committed reports reject transcript, prompt, response, evidence, participant, private-path, or sentinel content.
