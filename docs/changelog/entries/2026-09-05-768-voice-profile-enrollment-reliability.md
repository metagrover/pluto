### Make remembered voices durable and visible in People Pro

- **Issue:** [#768](https://github.com/metagrover/pluto/issues/768)
- **PR:** Pending.
- **Changed:** Speaker review now carries each stored candidate's exact transcription revision into matching, rejection, and enrollment; enrollment remains available when automatic suggestions are disabled; and newly created People are enrolled through the person ID returned by the confirmed meeting binding. When final transcription did not persist a candidate, the explicit “Remember this voice” action now analyzes the same two bounded system-audio samples offered in Speaker Identification, requires one unambiguous candidate to pass the existing purity gates, and persists the candidate plus enrollment in one transaction. The native evidence pipeline retains speaker-masked embeddings backed by clean system speech and filters only deviant observations when a stable majority remains. Explicitly enrolled active profiles participate in future-meeting suggestions without a hidden flag, while disabled profiles remain inert. People Pro plays the same system-channel reference audio and distinguishes a profile-loading failure from a person who has no enrolled voice.
- **Why:** Checking “Remember this voice for future meetings” could save the meeting identity while silently rejecting or skipping the voice enrollment. Valid production embeddings were also discarded when their public diarization span crossed short clean-speech intervals, leaving recurring peers unidentified and their People Pro Voice Profile empty.
- **Replaced:** Finalization-only enrollment candidates, whole-span containment for already speaker-masked embeddings, placeholder `gen-1` candidate revisions, inert enrolled profiles behind a calibration flag, microphone-channel profile playback, silent enrollment failures, and People Pro's ambiguous empty state after a profile read failure.
- **Notes:** Voice matching remains an explicit, reversible suggestion rather than a silent identity overwrite. Pluto does not bulk-enroll historical identity bindings: a person is enrolled only when the user explicitly checks “Remember this voice,” including when revisiting an older meeting. Existing meetings no longer require transcript regeneration to create that profile.
