### Bring the next two meetings into the dashboard

- **Issue:** [#617](https://github.com/metagrover/pluto/issues/617)
- **PR:** Not created yet.
- **Changed:** Pluto can request native macOS Calendar access, choose one calendar in place on the Dashboard, and show the next two meetings as a divider-free agenda with an inline `See more` reveal. The selected source now sits in quiet metadata beneath the agenda instead of competing with its heading. The selection remains durable when the first event read needs recovery, and native responses with omitted optional event fields are normalized instead of rejected. Calendar context appears during recording and on matched meeting records. Recent win moves below upcoming meetings and the previous continuation card is removed.
- **Why:** A hosted Google OAuth client conflicts with Pluto's free, local-first, one-click distribution goal, while calendars already configured on a Mac provide the same context without Pluto operating an authentication service. Setup now finishes where calendar context becomes useful instead of interrupting the Dashboard with a trip to Settings.
- **Replaced:** The empty upper-right dashboard rail, the dashboard continuation card, the first-run Settings redirect, the truncated heading-row calendar badge, event-row dividers, and false read failures caused by valid native timestamp or optional-field encodings.
- **Notes:** Pluto asks only after an explicit user action. macOS grants full Calendar permission because EventKit has no read-only access tier, but Pluto's native bridge exposes read operations only. The integration stores a bounded minimal cache, preserves provenance, selects one calendar at a time, never edits events, and does not send calendar fields to meeting intelligence prompts. Settings remains available for later maintenance.
