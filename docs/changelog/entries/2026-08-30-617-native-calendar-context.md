### Bring the next two meetings into the dashboard

- **Issue:** [#617](https://github.com/metagrover/pluto/issues/617)
- **PR:** Not created yet.
- **Changed:** Pluto can request native macOS Calendar access, choose one or multiple calendars on the Dashboard and in Settings, show the next two meetings as a divider-free agenda with an inline `See more` reveal, and quietly summarize multiple selected calendars in the footer. Live calendar discovery refreshes sources via `EKEventStore.refreshSourcesIfNecessary()` when opening Change or refreshing. Events from all selected calendars are merged into an atomic cache revision, preserving prior cache upon partial failure. Change navigates directly to Settings → Meetings and refreshes inventory.
- **Why:** A hosted Google OAuth client conflicts with Pluto's free, local-first, one-click distribution goal, while calendars already configured on a Mac provide the same context without Pluto operating an authentication service. Users often maintain separate personal and work calendars (including CalDAV/Google sync accounts in Apple Calendar) and need all relevant calendars represented without application restarts.
- **Replaced:** The single selected-calendar constraint, static calendar inventory enumeration without source refresh, the first-run Settings redirect, and Dashboard Change navigating to Personal settings.
- **Notes:** Pluto asks only after an explicit user action. macOS grants full Calendar permission because EventKit has no read-only access tier, but Pluto's native bridge exposes read operations only. Database migration is additive via `selected_calendars_json` while mirroring the first calendar into `selected_calendar_json` for rollback compatibility. Pluto stores a bounded minimal cache, preserves provenance, never edits events, and does not send calendar fields to meeting intelligence prompts.
