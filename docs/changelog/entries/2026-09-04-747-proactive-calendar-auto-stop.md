### Proactive calendar session auto-naming, start prompts, and silence-based auto-stop

- **Issue:** [#747](https://github.com/metagrover/pluto/issues/747)
- **PR:** [#754](https://github.com/metagrover/pluto/pull/754)
- **Changed:** Added proactive calendar event detection at recording startup that immediately sets session titles and supplies organizer and attendee names as meeting-scoped transcription hints without treating invitees as confirmed People. Added non-intrusive floating pill start prompt banners for upcoming or starting conference meetings (Zoom, Google Meet, Teams, Webex, Slack) when idle with 1-click recording start. Implemented a compact speaker-review flow above the transcript: anonymous remote clusters display as `Speaker N`, include transcript context and on-demand isolated voice samples, and let users explicitly bind a speaker to an invited attendee, an existing person, or a new person. Confirmed bindings update the meeting display immediately, contribute direct confirmed evidence in People, and support Undo without rewriting canonical transcript labels. Implemented a capture silence watchdog that automatically seals the capture journal and ends sessions with explicit `end_reason` when continuous silence extends past the scheduled meeting end time or when conference audio ceases, and pushes desktop notifications when notes are ready. Added user configuration toggles and timeout selector in Settings → Meetings.
- **Why:** Reduces manual input friction when starting sessions during scheduled meetings, prevents missing recordings for active video conference calls, and avoids bloating capture records with trailing silence when users forget to stop recording.
- **Replaced:** Manual session naming, form-first anonymous speaker corrections, and manual-only session stopping.
- **Notes:** Silence auto-stop is configurable via Settings → Meetings with options for 3m, 5m (default), 10m, or disabled. Persistent cross-meeting voice recognition is intentionally deferred to [#755](https://github.com/metagrover/pluto/issues/755).
