### Harden Phi notes behind a source-first experiment
- **Issue:** [#788](https://github.com/metagrover/pluto/issues/788)
- **PR:** [#794](https://github.com/metagrover/pluto/pull/794)
- **Changed:** Added canonical visible-block scoring, frozen semantic and capacity fixtures, bounded source-first inventory reconciliation, one mandatory final editor, strict paired-evaluation manifests and durable ledgers, plus real provider-to-SQLite publication and downstream packaging checks in a disposable profile. Added harness-specific TypeScript validation and deterministic source-edit, cancellation, transport-failure, and interrupted-run recovery checks.
- **Why:** Phi was faster on the 16 GB reference Mac but still omitted or mis-associated critical meeting facts that automated triage had accepted.
- **Replaced:** The earlier candidate evaluation could score flattened output and stop dry runs at the first request, so an experiment label did not prove the source-first route or final editor actually ran.
- **Notes:** Added paired downstream fixtures through the real dreaming coordinator and proposal store, original-source oracle checks, duplicate prevention, and foreground/source-change cancellation with retry. These use scripted model responses. The experiment remains disabled by default; promotion still requires fresh model runs, human review, and sustained application acceptance.
- **Verification follow-up:** Added a guarded real-Electron driver with renderer IPC, installed-model requests, one-second resource/run telemetry, durable physical-request evidence, process-kill/relaunch recovery, and repeated cancellation. It preserves rejected model retries as failures. A live source-edit retry still fails strict validation; no prompt relaxation or production routing change was retained.
