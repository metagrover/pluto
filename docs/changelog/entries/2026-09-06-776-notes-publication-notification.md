### Publish safe local notes and announce them truthfully

- **Issue:** [#776](https://github.com/metagrover/pluto/issues/776)
- **PR:** Pending.
- **Changed:** A direct compact writer retries one truncated response with the concise contract. A compact Ollama notes run retains its deterministically accepted writer draft when the complete-document editor truncates or fails semantic validation. Renderer progress refreshes remain available throughout the run, while the native “Meeting notes ready” notification is emitted only after the notes are durably published. Terminal metrics are best-effort, so deleting a meeting during generation cannot replace cancellation with a foreign-key failure or suppress a successful publication notification. Primary and secondary analysis now receive resolved self and participant display names, with identity changes included in the notes cache key.
- **Why:** Older meetings either reached the local model output limit or spent minutes completing both passes before discarding a safe writer draft because the editor response failed semantic validation. The same generic update callback also announced readiness for queued and running stages, and the notes prompt received raw anonymous labels even when Pluto had a trusted identity binding.
- **Trust:** Invalid source references, inherited-commitment violations, unsafe writer drafts, transport failures, cancellation, and stale publication still fail closed. Fallback notes are marked as complete with warnings rather than claiming a clean model audit. Unbound speakers remain anonymous; Pluto applies names only from the self profile or an explicit meeting identity binding.
- **Replaced:** Immediate direct-writer truncation failure, terminal failure after an otherwise safe writer result, and native readiness notifications on non-terminal progress updates.
- **Notes:** The renderer continues receiving all meeting-note progress updates; only the native operating-system notification moved to the durable publication boundary.
