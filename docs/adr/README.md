# Architecture Decision Records

Use ADRs for high-impact technical decisions that future engineers or agents will need to understand in depth.

Most decisions should stay in `docs/decisions.md`. Create an ADR only when all of these are true:

- There are multiple credible options.
- The decision has long-lived technical consequences.
- Future work would suffer without the rationale and tradeoffs.

## ADR Format

```markdown
# YYYY-MM-DD - Decision title

## Status
Proposed | Accepted | Superseded

## Context
What problem, constraint, or product direction forced this decision?

## Decision
What did we choose?

## Alternatives Considered
- Option A: tradeoff.
- Option B: tradeoff.

## Consequences
What this enables, constrains, risks, or requires later.

## Links
- Issue: #123
- PR: #456
```
